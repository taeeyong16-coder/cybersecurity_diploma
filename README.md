# Система гібридного захисту PDF-документів (HDPS)

Дана програма розроблена для забезпечення цілісності та автентичності офіційних документів (сертифікатів, заяв, довідок) за допомогою поєднання криптографічних цифрових підписів та стеганографічного приховування даних.

## Функціонал програми

Система складається з двох основних модулів управління: графічного інтерфейсу (GUI) та консольного інструменту (CLI).

### 🖼 Графічний інтерфейс (GUI)
*   **Запуск**: `python gui_app.py`
*   **Опис**: Інтуїтивно зрозуміле вікно для індивідуальної роботи з документами.
*   **Можливості**:
    *   Доступні всі шаблони: **Cyberverse Certificate** (сертифікат за призове місце), **Cyberverse Participation Certificate** (сертифікат учасника), **Certificate of Achievement**, **Application Form** (заява), **Contract for Education** (контракт на навчання).
    *   Повний цикл роботи: генерація захищеного документа та його миттєва перевірка.
    *   Зручне введення персональних даних та вибір дати за допомогою календаря.
*   **Особливість**: GUI версія призначена для поштучного створення документів. **Масова генерація тут відсутня.**

### 💻 Консольний інтерфейс (CLI)
*   **Запуск**: `python cli_batch_gen.py`
*   **Опис**: Потужний інструмент для автоматизації та масової обробки великої кількості документів.
*   **Можливості**:
    *   **Масова генерація**: Дозволяє автоматично створити сотні документів на основі даних із зовнішнього файлу. Найбільш зручно використовувати для масової видачі сертифікатів (наприклад, після конференції).
    *   **Масова перевірка**: Можливість перевірити валідність усіх PDF-файлів у вказаній папці одним натисканням.
*   **Вимоги до даних (CSV)**: Програма заточена під читання файлів `.csv`. Для коректної масової генерації сертифікатів файл має містити 4 колонки:
    1.  **Прізвище**
    2.  **Ім'я**
    3.  **По батькові**
    4.  **Місце** (зайняте місце або роль). *Для шаблону **Cyberverse Participation Certificate** ця колонка ігнорується.*

#### 💡 Як правильно користуватися CLI:
1.  **Запуск**: Відкрийте термінал у папці проекту та введіть `python cli_batch_gen.py`.
2.  **Вказання шляхів**: Якщо шлях до файлу або папки містить пробіли, обов'язково беріть його в лапки, наприклад: `"C:\Users\Admin\Documents\my participants.csv"`.
3.  **Перевірка**: При виборі опції перевірки вкажіть шлях до папки з документами. Система просканує всі PDF-файли за цим шляхом.

## Алгоритм роботи системи

### Етап 1: Підготовка та генерація
1.  **Вибір документа**: Користувач обирає тип шаблону (сертифікат, заява тощо).
2.  **Персоналізація**: Заповнюються дані (ПІБ, ідентифікатор, дата).
3.  **Підпис**: Додається PNG-зображення власноручного підпису.
4.  **Формування PDF**: Дані накладаються на відповідний PDF-шаблон.

### Етап 2: Захист (Криптографія та Стеганографія)
1.  **Канонізація тексту**: Текст документа приводиться до суворого стандарту (видалення зайвих пробілів, уніфікація символів). Це гарантує, що при перевірці не виникне помилок через невидимі знаки.
2.  **Хешування**: Канонізований текст перетворюється на унікальний відбиток за алгоритмом **SHA-256**.
3.  **Цифровий підпис**: Хеш підписується приватним ключем видавця за допомогою алгоритму **ECDSA (SECP256R1)**.
4.  **Шифрування**: Отриманий цифровий підпис шифрується симетричним алгоритмом **AES-GCM** для захисту від прямого зчитування сторонніми особами.
5.  **Вбудовування (LSB)**: Зашифрований підпис ховається у фоновому зображенні документа за допомогою стеганографічного методу **LSB (Least Significant Bit)**. Модифікуються найменш значущі біти пікселів RGB-каналів. Зміни неможливо помітити візуально. Стеганографічний фон вставляється у фінальний PDF.

### Етап 3: Верифікація (Адміністратор)
1.  **Вилучення**: З PDF-файлу автоматично витягується фон.
2.  **Відновлення**: Методом зворотного LSB із фону вилучається зашифрований блок.
3.  **Дешифрування**: Блок розшифровується за допомогою AES-GCM ключа.
4.  **Порівняння**: З PDF витягується видимий текст, канонізується та повторно хешується. За допомогою відкритого ключа (Public Key) перевіряється справжність підпису.

**Статуси перевірки:**
✅ **VALID** — Підпис справжній, документ автентичний, втручання не виявлено.
❌ **TAMPERED** — Виявлено модифікацію тексту або фонового зображення документа. 
⚠️ **UNSIGNED** — Документ не містить цифрового захисту цієї системи.

## Встановлення та запуск

1.  Встановіть необхідні бібліотеки:
    ```bash
    pip install cryptography Pillow pymupdf reportlab tkcalendar
    ```
2.  При першому запуску (`gui_app.py` або `cli_batch_gen.py`) система автоматично створить ключі (`private_key.pem`, `public_key.pem`, `aes_key.bin`) та сервісні файли, якщо їх немає.

> **Важливо**: Зберігайте файли ключів та `stego_seed.bin`. Без них верифікація раніше створених документів буде неможливою!
